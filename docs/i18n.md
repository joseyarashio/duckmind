# The simulator pages in six languages

Rule (in [CONTRIBUTING.md](../CONTRIBUTING.md)): the simulator pages speak six languages. 繁體中文 (`zh-Hant`)
is the default and the source. English (`en`), 日本語 (`ja`), Español (`es`), 简体中文 (`zh-Hans`) and
한국어 (`ko`) are translations in the same plain style. Every page change ships its words in all six
in the same change. Never send page text to an outside translation service.

## Where things live

| What | Where |
|---|---|
| Catalogs, one file per language and domain | `src/duckmind/simweb/static/i18n.<lang>.<domain>.js` |
| Which catalog files exist | `static/i18n.manifest.js` (written by the tools) |
| Page runtime | `static/i18n.js` (`window.I18N`), `static/i18n.css` |
| Translator notes: where a text shows, tone, room, values | `src/duckmind/i18n/context.json` |
| Fixed terms for all five translators | `src/duckmind/i18n/glossary.json` |
| Page words that may stay outside the catalogs (names, language names) | `src/duckmind/i18n/allowlist.json` |
| Python side: messages, ICU, checks, tools | `src/duckmind/i18n/*.py` |
| Server answers get `_i18n` maps | `src/duckmind/simweb/i18nwire.py`, `i18n/boundary.py` |

A catalog file is one call, `DuckI18n.load("en", "page", {...})`, with strict JSON inside: sorted
keys, one message per line. Do not edit them by hand; use the tools below.

Domains are chosen by the first segment of a key:

* `page` (also `fmt`, `lang`): the page's own words, formats, language names.
* `web`: the simulator server.
* `core` (also `world`, `curiosity`, `bodyhost`, `livebody`, `eye`): Duck Core, the world, the body, the eye.
* `neuro`: the neural duck.

The 繁體中文 page loads only the `page` catalog. The other five load every domain. So code that runs
in the browser may name only `page.*` and `fmt.*` keys (`tests/test_i18n_page_keys_loaded.py`).

Keys look like `page.live.who`: lowercase namespace, then dotted segments. A key keeps its meaning.
If the 繁體中文 words change meaning, make a new key. If they change only in wording, run
`python -m duckmind.i18n restamp KEY` and keep the translations.

## Messages

Messages use a small ICU MessageFormat subset (the same in `i18n/icu.py` and `static/i18n.js`):

* `{name}` a value; `{n, number}`, `{n, number, ::.0}` a number.
* `{n, plural, one {# day} other {# days}}`, `selectordinal`, and `{x, select, a {...} other {...}}`.
* Every translation must use the same values as the source and only the plural forms its language has.
  `''` is a literal apostrophe; `'{'` is a literal brace.

## Names are data

The duck's name, people's names, and what the family typed are data. They are passed as values
(`{name}`), shown as they are, and never translated or keyed. Names that may appear alone in the page
(蛋黃, 阿勇, 怯怯, 慢慢, 啾啾, 小鴨) are listed in `allowlist.json`. A speaker role such as 主人 is a word
and has a key.

## In the page (HTML and JS)

* HTML text: write the 繁體中文 words for the first paint and mark the element with
  `data-i18n="page.some.key"`. The words in the HTML must equal the catalog's 繁體中文 text.
* Attributes (aria-label, title, placeholder): `data-i18n-attr="aria-label:page.some.key"`.
* Text with markup: `data-i18n-html`.
* Server text fields: `data-i18n-field` and `I18N.field(obj, "note")`.
* In scripts: `I18N.t(key, params)`, `I18N.text(el, key, params)`, `I18N.attr(el, name, key, params)`.
  The `text`/`attr` forms remember how, so a language switch re-renders them. Canvas labels use `I18N.t`
  and are redrawn on `I18N.onChange`.
* Formats that follow the language: `I18N.number`, `time`, `date`, `list`, `relTime`.
* The language comes from `?lang=`, then the viewer's own choice (stored in the browser), then
  `navigator.languages`, then 繁體中文. `?lang=pseudo` wraps every catalog text in `⟦ ⟧`: any words outside the brackets are
  hard-coded.

## In Python (server and brain)

`msg("web.some.key", n=3, name=duck_name)` returns a `Msg`. A `Msg` is the 繁體中文 `str` it replaces
(so old code and tests keep working) and remembers its key and values. Use `lst([...])` for a list
and `join(a, b)` to glue words. Do not build page text with f-strings.

Before an API answer is sent, `i18nwire` adds an `_i18n` map next to every field that holds page words:
field name to `{k: key, p: params}`. The words stay 繁體中文. The browser shows the `_i18n` message in
the viewer's language. Text that crossed the physics body's socket keeps the map the body process
attached. Frozen-engine words (the v4_0 Duck Core that 蛋黃 runs on) are matched back to the engine's
own templates; the engine is never edited. Fields that are data are never keyed (see `DATA` in
`i18n/boundary.py`).

## How to add a word in six languages

1. Pick a key (`page.live.guest_note`). Use the `page` domain for anything the browser draws.
2. Add the 繁體中文 source and its context:

   ```
   python -m duckmind.i18n add page.live.guest_note "訪客說話，小鴨不認得" \
       --where "talk panel, under the speaker chooser" --kind static --latin 40 --one-line
   ```

   `--kind` is one of `static`, `attr`, `canvas`, `template`, `server`, `format`. `--tone`, `--latin N`
   (Latin letters that fit on one line at 390 px) and `--file F --line N` are optional.
3. Add the other five, one command each (the tool checks that the message parses, has the same values and
   valid plurals):

   ```
   python -m duckmind.i18n set en page.live.guest_note "..."
   python -m duckmind.i18n set ja page.live.guest_note "..."
   python -m duckmind.i18n set es page.live.guest_note "..."
   python -m duckmind.i18n set zh-Hans page.live.guest_note "..."
   python -m duckmind.i18n set ko page.live.guest_note "..."
   ```

   For many words: `export LANG --missing -o file.json`, fill the file, `import LANG file.json`.
   New words in 日本語, 简体中文 or 한국어: run
   `uv run --with fonttools --with brotli python -m duckmind.i18n.fonts subset` (the page's Noto JP/SC/KR
   are subsets of the catalogs' glyphs; `tests/test_i18n_fonts.py` fails until you do).
4. Use the key in the page or in Python as above.
5. Check the layout in the longest language (usually Español or 日本語) at 1440x900 and 390x844.
6. Run `python -m duckmind.i18n check` and the tests below.

## Commands

Run from the repository root with `PYTHONPATH=src` (or the project's virtualenv). Options `--static DIR`,
`--root DIR` and `--context FILE` come before the command and are for tests that work on a copy.

| Command | What it does |
|---|---|
| `check` | Everything the tests check, as a list; exit 0 means no problem |
| `stats` | Keys per domain and how much of each language is done |
| `find WORDS\|KEY` | Search the 繁體中文 source and the keys |
| `add KEY "text" --where "..."` | A new source string and its context |
| `set LANG KEY "words"` | One checked translation |
| `export LANG [--missing] [--domain D] [-o FILE]` | A translator's file: key, 繁體中文, where, tone, room, values, current words |
| `import LANG FILE [--force]` | Translations back in |
| `restamp KEY` | After a same-meaning fix of a 繁體中文 text |
| `format` / `manifest` | Rewrite catalog files canonically / rewrite `i18n.manifest.js` |
| `pseudo KEY [values-json]` | One message in the pseudo-locale |
| `scan` | Page words that do not come from a catalog |
| `pack v4_0\|v4_1` | The engine pack: templates, keys, keys missing from the catalog |

## Tests

```
PYTHONPATH=src python -m pytest tests/test_i18n_*.py
```

* `test_i18n_catalog.py`: every key in every language, same values, valid plurals, context present and
  current (a changed source text under an old key fails).
* `test_i18n_page_text.py`: no page words outside the catalogs; HTML first-paint words equal the catalog.
* `test_i18n_page_keys_loaded.py`: page code names only keys the browser loads.
* `test_i18n_runtime_js.py`: `i18n.js` and the Python side render the same words (needs Node).
* `test_i18n_icu.py`, `test_i18n_message.py`, `test_i18n_boundary.py`, `test_i18n_tools.py`: the message layer,
  the `_i18n` boundary on real engine output, and the tools. `tests/test_live_voice_page.py` also checks
  that every word of the talk panel exists in all six languages.
