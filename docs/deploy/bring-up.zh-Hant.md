# 第一隻真鴨子的啟動步驟：先孵窩，再破殼

English: [bring-up.md](bring-up.md)

**狀態：還沒有在真機上跑過。** 目前還沒有接過任何一隻量產 Microduck。這裡的每一條指令都在模擬鴨子
（`sim-body --as-real`，也就是「演練」）和測試用的假身體上跑過。標「演練」的數字是在那裡量的，
對真鴨子還不代表什麼。

這是第一隻量產鴨子的階梯，一共五個階段。前一階段通過了才能進下一階段。每個階段的通過數字都是
**先寫下來、再看資料**的（2026-11-10 登記）。沒達到就是沒過：不要改數字，退回上一階段找原因。

這一頁不取代下面三份：

- [SAFETY.md](../../SAFETY.md)：Duck Mind 為了安全做什麼、不做什麼。
- [docs/real-microduck.zh-Hant.md](../real-microduck.zh-Hant.md)：電腦上的大腦怎麼連到鴨子（橋、
  金鑰、`check`），以及**第一隻真鴨子的檢查清單**。這一頁只說每個清單項目「什麼時候做」，項目
  本身寫在那裡。
- [docs/deploy/board.md](board.md)：確認板子、安裝檔、退回（§4）、關掉 mediad 在區網上的門（§5）。

## 每個階段都適用的規則

1. **兩個人。** 一個在電腦前；一個手放在鴨子旁邊，鴨子自己的電源開關伸手就碰得到。`robot.stop`
   不是緊急停止（[SAFETY.md](../../SAFETY.md)）：它只讓走路歸零，不會切掉馬達的力。真正的緊急
   停止是那隻手和那個開關。
2. **Duck Mind 絕不替鴨子開機。** 由人用鴨子自己的控制來開。真鴨子上的橋會拒絕 `robot.enable`、
   `robot.init`、`robot.poseJoints`。
3. **一個紀錄資料夾**（下面叫 `SESSION`，自己選一個放在 repo 外面的資料夾）。每個階段都往裡面
   加檔案。橋啟動時加 `--events SESSION/bridge-events.jsonl`（在鴨子上；每個階段結束時複製回來）。
4. **階段紀錄。** `SESSION/stage-N.md`：日期、在場的人、`check` 印出的軟體版本、每個通過數字和
   量到的值，最後一行寫「cleared by <名字>」或「not cleared: <原因>」。**只有主人能放行一個階段。**
   程式和寫程式的 AI 都不能。
5. **中止的意思是：停下來，必要時用手關電源，寫下發生了什麼，退回上一階段。** 前面階段的中止
   條件在後面每個階段都還有效。
6. **退回只要刪一個檔。** 大腦只有在「這塊板子 + 這兩個網路」有一份有效的身體校正檔時才會讓真
   鴨子走路（階段 3）。把那個檔刪掉（`python -m duckmind.bringup show URL` 會印出路徑），大腦
   下次啟動就又只動頭了。板子上的軟體退回見 [board.md §4](board.md)。

下面用到的兩個簡寫：

```sh
URL=remote://<鴨子的位址>:8797          # 鴨子上的橋（docs/real-microduck.zh-Hant.md 第 4 步）
SESSION=<這次啟動的紀錄資料夾>          # 放在 repo 外面
```

## 階段 0：只讀，什麼都不動

**進入條件。** 鴨子放在架子上或坐在桌上，有電，**還沒開機（enable）**。板子確認過
（[board.md §1](board.md)）。Wi-Fi、金鑰、橋都設好了
（[real-microduck.zh-Hant.md](../real-microduck.zh-Hant.md) 第 1–4 步）。mediad 在區網上的門關好了
（[board.md §5](board.md)）。

**指令。**

```sh
# 在鴨子上（Pollen 自己的工具；輸出留下來）
robotctl health

# 在電腦上
python -m duckmind.remotebody check $URL --wifi-minutes 10 | tee $SESSION/stage0-check.txt
python -m duckmind.bringup show $URL                       # 應該看到：no valid calibration (none): head only
python -m duckmind.bringup watch $URL --out $SESSION --minutes 5
```

**要留的紀錄。** `stage0-check.txt`、`watch-*.json`、`robotctl health` 的輸出、events 檔。

**通過。** N1、N2、N3，再加上 `check` 印出的這幾行：

- 印出走路和坐站兩個網路的 sha256，以及是哪一套（v8 或 v9：見「要問主人的事」）；
- `robotd.toml`：`idle False`（不是的話 `check` 會說要在鴨子上改什麼）；
- `usage data (Pollen telemetry): off`；
- mediad 的門：`check` 說從電腦連 8443 和 8080 **沒有**回應；
- events 檔裡沒有 `refused_operator`（沒有任何東西叫 robotd 開機）。

這裡順便完成的清單項目（[real-microduck.zh-Hant.md](../real-microduck.zh-Hant.md)）：鴨子上的橋、
API 版本、時鐘、家裡 Wi-Fi 品質、電量讀數、相機過連線、其他的門、板子的 CPU。

**中止。** 鴨子動了（我們什麼都沒叫牠做）。門關不起來。`check` 失敗。沒有回報電流（這樣這版
robotd 上就不可能有腳負載的感覺：停下來問 Pollen）。

**放行：** 主人。**退回：** 把橋停掉；鴨子上什麼都沒改。

## 階段 1：腳離地

鴨子被人托著身體，或放在架子上、腳懸空。這個階段牠做什麼都不會跌倒。

### 1a. 只動頭（10 分鐘）

**進入條件。** 階段 0 放行。由人用鴨子自己的控制把牠開起來（寫下是用哪一個控制：這是清單項目）。

**指令。** 照 [real-microduck.zh-Hant.md](../real-microduck.zh-Hant.md)「在真的小鴨上開頁面」啟動
頁面，多加 `--neuro-record $SESSION/stage1-neuro.jsonl`。「真的小鴨」那張卡要顯示「只動頭、不走路，
因為還沒量過牠的身體校正」（現在還沒有校正檔，這是預期的，也正是讓腳不動的原因）。讓牠跑 10 分鐘，
然後停掉頁面（Ctrl-C）：橋會讓鴨子停下並坐好。

**通過。** N6；頭都在範圍內（之後 `robotctl health` 沒有馬達警告）。清單裡的**頭部動作**和
**頁面的真鴨子模式**（畫出來的姿勢和鴨子一樣、眼睛視窗看得到牠的相機）也在這裡檢查。

**中止。** 腳動了。頭撞到極限或線。馬達警告。

### 1b. 腳懸空（工作台錄音，階段 1）

**進入條件。** 1a 通過。頁面已停掉（橋一次只服務一個電腦程式）。

**指令。**

```sh
python -m duckmind.bringup record $URL --out $SESSION --stages 1 --drive --unit "<您取的名字>"
```

工具每錄一段之前會說要怎麼擺，等您按 Enter：坐姿托在空中（8 秒）、站姿托在空中（10 秒）、然後
腳會**在空中踏步** 4 秒再停。加了 `--drive`，工具自己送「坐／站切換」和那一個慢走指令，其他什麼
都不送。不加 `--drive` 它就只讀（結束時送一次停止），姿勢由人用鴨子自己的控制來換。

接著做三次斷線保護：再跑一次同一條指令，腳在空中踏步的時候把連線切掉（關掉電腦的 Wi-Fi，或
`kill -9` 這個工具）。橋必須自己讓鴨子停下並坐好。

**要留的紀錄。** `SESSION/recording.jsonl.gz`（每個階段工具都往同一個檔後面加）、events 檔、
三次切斷的手機影片。

**通過。** 三段都錄到了（沒有作廢的）；N4；N5（3 次全過）。寫下 robotd 自己的「被抱起來暫停」
有沒有啟動（policy 顯示 `held`）：那是 Pollen 的偵測，之後報告會寫出來。

**中止。** 關節撞到硬極限、線被勾住、馬達警告、切斷後腳沒有停。

**放行：** 主人。**退回：** 階段 0。

## 階段 2：在地上：站、坐、被抱起來

**進入條件。** 階段 1 放行。至少 1 m × 1 m 的平整空地，沒有邊緣，手在鴨子旁邊。N3。

**指令。**

```sh
python -m duckmind.bringup record $URL --out $SESSION --stages 2 --drive
python -m duckmind.bringup fit $SESSION          # 還不要加 --save
```

錄的內容：坐在地上（8 秒）、站著（12 秒）、坐下－站起 5 次、站著被抱起 3 次、坐著被抱起 3 次
（工具會說 LIFT 和 SET DOWN；抱高約 20 公分、拿穩不動、放回原地），最後是 ToF：拿一塊平的板子
（一本書）貼著鴨子的臉，再放在感測器前 30、60、100、150、200、300 mm（用尺量；每個距離 3 秒）。

`fit` 會寫出 `SESSION/report.md` 和 `SESSION/fit.json`。這個階段它應該說 **NOT YET**，而且原因
只有一個：*the segment walk was not recorded*（還沒錄走路）。

**要留的紀錄。** 錄音檔、`report.md`、`fit.json`、坐站和抱起的影片。

**通過。** N7、N8、N9、N11、N4。請讀報告裡 *What this body's leg load cannot tell apart* 那一節：
每一行是一個在這隻鴨子上不管用的判斷，以及改由什麼來補。

**中止。** 坐下－站起時跌倒（用手扶起來；找過原因後可以重做一次，第二次跌倒就結束這個階段）。
報告說「站著在手上」和「站著在地上」分不開（N8）：那大腦就不能靠腳負載帶這隻鴨子走路，這個
階段到此為止，把這個發現交給主人。

**放行：** 主人。**退回：** 階段 1。

## 階段 3：有人看著，在 1.5 m 的空方框裡走

用至少 15 公分高的板子圍出 1.5 m × 1.5 m 的方框（ToF 要看得到板子），裡面什麼都沒有，手全程在
鴨子旁邊。**第一次要不要讓牠走路，由主人決定**（見「要問主人的事」）；沒有這個決定，啟動就停在
階段 2。

### 3a. 工作台走路，產生校正檔

```sh
python -m duckmind.bringup record $URL --out $SESSION --stages 3 --drive
python -m duckmind.bringup fit $SESSION --save
```

走三次：用最慢的走路往前 4 秒（約 0.6 m）、停、3 秒。`fit --save` 只有在全部通過時才會安裝校正檔，
並印出路徑。

**通過。** N10，而且報告的結論是 **PASS**。這時 `python -m duckmind.bringup show $URL` 會印出校正檔。

### 3b. 地上觀察（10 分鐘，不開大腦）

```sh
python -m duckmind.bringup watch $URL --out $SESSION --minutes 10
```

鴨子在地上站著、坐著（用牠自己的控制換幾次），沒有人碰牠。**通過。** N12。

### 3c. 地上的斷線保護（切 5 次）

再跑一次 `record --stages 3 --drive`，寫到**新的**資料夾（`--out $SESSION/deadman`），每次走路時
把連線切掉，共 5 次。**通過。** N5（5 次全過），沒有跌倒。

### 3d. 大腦帶牠走（15 分鐘）

啟動頁面，加 `--neuro-record $SESSION/stage3-neuro.jsonl`。「真的小鴨」卡要顯示「連著」，沒有
「只動頭」那一行。讓牠在方框裡自己走 15 分鐘。然後在牠走路時把牠抱起來，5 次（N14）。

**要留的紀錄。** neuro 紀錄檔、events 檔、15 分鐘全程影片、寫了次數的階段紀錄（頁面顯示「被抱
起來」但沒有手碰牠，就算一次誤判）。

**通過。** N13、N14、N4。

**中止。** 跌倒。兩次走到方框邊變成頂著推。誤認被抱起超過兩次（每次牠都會坐下）。電量低於 30 %。
第二次斷線。任何需要伸手的情況。

**放行：** 主人。**退回：** 刪掉校正檔（規則 6）：大腦又只動頭。然後回階段 2。

## 階段 4：在一間清空的房間裡自由走

**進入條件。** 階段 3 在兩個不同的日子都放行過。一間房間，門關著，地板清空：沒有電線、沒有樓梯
或邊緣、沒有水、沒有寵物或小小孩、沒有 ToF 看不到又爬得上去的矮東西（20 mm 的門檻會讓牠跌倒：
這是已知、已接受的限制）。房間裡一直有人。真鴨子上充電和充電座是關掉的（牠沒有「充電中」的
訊號）；牠結束時會坐下來要人幫忙，由人換電池或充電。

**指令。** 和 3d 一樣開頁面，三次、每次 30 分鐘，每次各自一個 `--neuro-record` 檔。兩次之間跑
`python -m duckmind.remotebody check $URL`（電量、連線）。

**要留的紀錄。** 和 3d 一樣，每次一份。

**通過。** N15、N4。

**中止。** 和階段 3 一樣，再加上：跌倒後爬不起來；同一個東西被頂著推兩次。

**放行：** 主人。把鴨子單獨留在房間裡，就是「破殼」的決定，**不在**這個階梯裡：要階段 4 連續
兩週沒有中止之後才談（主人的原則：先孵窩，再破殼）。

**退回：** 階段 3（方框），或規則 6。

## 什麼時候要重量

大腦每次啟動都會拿校正檔和鴨子比對。下面的情況牠會自己退回「只動頭」，卡片上會說原因：

- 鴨子的走路或坐站網路換了（更新過：校正檔是別的網路的）；
- 板子換了（`robotd.toml` 裡的板子版本不同）；
- 檔案不見了或讀不出來。

另外，換過馬達或腳掌，或階段 4 的誤認被抱起超過 N15，也要重量：負載已經變了。重量一次是在新的
紀錄資料夾裡做 1b、2、3a（大約 15 分鐘）。

## 工作台工具到底做了什麼

`python -m duckmind.bringup`（在 `src/duckmind/bringup/`）：

| 指令 | 做什麼 | 會送給鴨子的 |
|---|---|---|
| `show URL` | 這台電腦有沒有這隻鴨子的校正檔，沒有的話為什麼 | 什麼都不送 |
| `watch URL --out DIR --minutes M` | 讀 M 分鐘的 `robot.state`；說出用這隻鴨子的校正檔，身體感覺會判斷出什麼；每 30 秒讀一次電量；連線的數字 | 什麼都不送 |
| `record URL --out DIR --stages …` | 有人帶著做的錄音 | 結束時一定會送歸零和 `robot.stop`；加 `--drive` 還會送 `sit_toggle`，以及每段走路一次「以 0.30 往前 4 秒」 |
| `fit DIR [--save]` | 算出門檻、把錄音重播給身體感覺、寫報告；`--save` 在通過時安裝校正檔 | （不連線） |
| `calibrate URL --out DIR` | 所有階段的 `record` 再 `fit --save`（給演練用；真鴨子請一個階段一個階段做） | 同 `record` |

校正檔是一份 JSON（`duckmind.body-calibration/1`），放在 `<duckmind home>/body-calibration/`，檔名
是板子加上兩個網路 sha256 的前幾碼。裡面有腳的負載門檻、ToF「貼臉」範圍，以及它們是怎麼來的。
模擬器自己的數字包在程式裡，永遠不會用在真鴨子上。

**先演練一次**（不需要機器人）：啟動 `python -m duckmind.remotebody sim-body --as-real …`，記下它
`remote-body: ready` 那一行裡的 `world_port`，然後跑

```sh
python -m duckmind.bringup calibrate remote://127.0.0.1:8797 --out $SESSION --drive --no-tof \
    --sim-person <world_port>
```

模擬世界裡的手會扮演那個人。演練在做完這一步之前，和真鴨子一樣只動頭。

## 要問主人的事

1. **第一次就可以走路，還是只動頭？** 沒有「可以」，啟動就停在階段 2（到那裡為止，所有東西都是
   在地上一步都沒走的情況下量的）。
2. **真鴨子用 v8 還是 v9？** 工廠映像檔正要換成 v9；模擬器裡的數字是 v8 比較好。校正檔是跟著
   網路的，所以要在 1b 之前決定，之後要換就得重量（15 分鐘）。
3. **第二個人是誰？** 緊急停止是一隻手。
4. **一隻還是好幾隻？** 校正檔是用板子版本和網路來認的，不是用單一隻鴨子（橋沒有回報序號）。
   如果有兩隻同樣板子的鴨子，在補上這個之前，每隻要用各自的電腦帳號或各自的 duckmind home。

## 這一頁沒有包含的

- 點地板「去那裡」：真鴨子上目前是拒絕的。
- 真鴨子上的充電座和充電，以及 mediad 的門開著時橋拒絕啟動：是另外的工作；做好之後這一頁會連過去。
- 麥克風和觸摸：沒有程式提供麥克風，鴨子也沒有觸摸感測器。
